# سامانه جامع آفلاین مدیریت تولید، بازبینی (QC)، کنداکتور و پلی‌اوت شبکه اصفهان (جهان‌نما)

**طراح و برنامه‌نویس:** شهاب‌الدین باقری دولت‌آبادی  
**مدیر پخش:** محمود فرشچیان  
**معماری:** ۱۰۰٪ آفلاین و مبتنی بر شبکه داخلی سازمان (Local Broadcast LAN)

---

## ۱. ویژگی‌های کلیدی و انطباق با الزامات برودکست

1. **عملکرد کاملاً آفلاین در زیرساخت محلی سازمان:**
   - ذخیره‌سازی متمرکز فایل‌های ویدئویی در پوشه محلی `./offline-data/media` و پوشه پایش خودکار شبکه `./offline-data/watchfolder`.
   - ذخیره‌سازی وضعیت کنداکتور، سوابق نسخه‌ها، نظرات بازبین و تصمیم‌های مدیریتی در `./offline-data/conductor-state.json` به همراه پشتیبان خودکار (`conductor-backup.json`).
   - استریم داخلی ویدئو از طریق `/api/media/[filename]` با پشتیبانی از `HTTP 206 Partial Content` جهت جلو و عقب بردن آنی و فریم‌به‌فریم (۲۵ فریم بر ثانیه) در مرورگر بدون نیاز به دانلود فایل.

2. **تفکیک دقیق ۶ نقش کاربری و سطوح دسترسی (همراه با پین‌کد محلی):**
   - **الف) تهیه‌کننده و تدوینگر (`پین: 1100`):** بارگذاری فایل ویدئویی، ثبت شناسه، مدت‌زمان، توضیحات و نسخه؛ مشاهده اصلاحیه‌های متصل به زمان/بازه زمانی؛ و ارسال نسخه اصلاح‌شده جدید (`v2`, `v3`) با حفظ کامل تاریخچه نسخه‌های قبلی.
   - **ب) واحد هماهنگی (`پین: 2200`):** دریافت فایل‌های جدید از تولید، ارجاع به بازبین مربوط، بازگرداندن اصلاحیه‌ها به تهیه‌کننده/تدوینگر و ارسال محتوای تأییدشده نهایی به صف برنامه‌ریزی و پلی‌اوت.
   - **ج) بازبین (`پین: 3300`):** مشاهده مستقیم ویدئو در پخش‌کننده داخلی، ثبت اصلاحیه در **زمان دقیق** یا **بازه زمانی مشخص (`از ... تا ...`)** و ثبت یکی از ۳ تصمیم: تأیید برای ادامه فرایند پخش، درخواست اصلاح، یا رد/ارجاع به مدیر پخش.
   - **د) مدیر پخش — محمود فرشچیان (`پین: 1405`):** بررسی پرونده‌های دارای درخواست اصلاح یا ارجاع‌شده برای تصمیم‌گیری مدیریتی؛ تأیید و بازگشت به هماهنگی یا الزام به اصلاح از مسیر هماهنگی به تولید.
   - **هـ) مسئول مدیریت پلی‌اوت (`پین: 4400`):** دریافت فایل‌های تأییدشده، کنترل پیش از پخش (`Pre-Flight Verification`)، تعیین محدوده زمانی مورد استفاده (`Mark In / Out`) و مدیریت ترتیب پلی‌لیست.
   - **و) اپراتور پایش پخش (`پین: 5500`):** حالت پایش صرف (`Read-Only Monitoring`) بدون مجوز تغییر فایل، زمان‌بندی، پلی‌لیست یا وضعیت تأیید؛ همراه با پایش تطابق اجرای پخش و ثبت و پیگیری خطاها در لاگ `As-Run`.

3. **یکپارچه‌سازی واقعی با سامانه پلی‌اوت و زنجیره پخش:**
   - **درگاه فرمان سخت‌افزاری (`/api/playout/execute`):** ارسال مستقیم دستورات استاندارد `AMCP` (`PLAY` / `LOADBG` با فریم دقیق `SEEK` و `LENGTH`) از طریق سوکت TCP به سرور پلی‌اوت محلی (`CasparCG Server` روی پورت پیش‌فرض `5250`).
   - **محافظ ایمنی پلی‌اوت (`Gatekeeper`):** جلوگیری سخت‌افزاری و نرم‌افزاری از اجرای فایل‌های تأییدنشده، ناقص یا دارای نسخه نامعتبر روی آنتن.
   - **خروجی تصویر خالص آنتن (`/playout-output`):** خروجی تمام‌صفحه `Clean Feed` همراه با لایه‌های گرافیکی زنده (`CG / DSK`) و حالت میز مانیتورینگ دوگانه استودیو (`Preview Split`) جهت اتصال به مبدل SDI.

## ۲. راهنمای اجرا در سرور شبکه داخلی (Windows / Linux LAN)

1. نصب وابستگی‌ها (یک‌بار در محیط استقرار):
   ```bash
   npm install
   ```

2. ساخت نسخه عملیاتی و اجرای سرور روی تمام اینترفیس‌های شبکه داخلی (`0.0.0.0:3000`):
   ```bash
   npm run build
   npx next start -H 0.0.0.0 -p 3000
   ```
   *(در سیستم‌عامل ویندوز می‌توانید از داخل سامانه، فایل اسکریپت `اجرای سرور مرکزی کنداکتور در ویندوز.bat` را دانلود و اجرا نمایید).*
